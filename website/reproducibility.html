One-command reproduction

# From a clean clone:
git clone https://github.com/kotz96-lab/TopicsSE_T1
cd TopicsSE_T1

# Set JAVA_HOME (once per shell)
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot"

# 1. Compile + JUnit5 + JaCoCo (~10 seconds)
./mvnw verify
# outputs:
#   target/site/jacoco/index.html         ← coverage report
#   target/surefire-reports/              ← JUnit results

# 2. PIT mutation coverage (~12 minutes with full 1948-test suite)
./mvnw -Ppit test
# outputs:
#   target/pit-reports/index.html         ← mutation report

# 3. Regenerate PICT tables (needs pict.exe locally under tools/ or on PATH; ~1 second)
pwsh scripts/generate-pict.ps1
# outputs:
#   pict/generated/regex-{2,3,4}wise.csv  ← byte-identical thanks to /r:1

Per-strength CIT reproduction (for §9.4 numbers)

# Six PIT runs, one per interaction-strength × oracle combination:
./mvnw -Ppit test -DincludedGroups=pict-2wise         # weak,   2-wise
./mvnw -Ppit test -DincludedGroups=pict-3wise         # weak,   3-wise
./mvnw -Ppit test -DincludedGroups=pict-4wise         # weak,   4-wise
./mvnw -Ppit test -DincludedGroups=pict-strong-2wise  # strong, 2-wise
./mvnw -Ppit test -DincludedGroups=pict-strong-3wise  # strong, 3-wise
./mvnw -Ppit test -DincludedGroups=pict-strong-4wise  # strong, 4-wise

Note the flag: -DincludedGroups= (PIT's own filter), NOT -Dgroups= (Surefire's, which PIT ignores). See the AI Tools page for why we know this the hard way.

Continuous integration

.github/workflows/ci.yml runs JUnit + JaCoCo + PIT on every push to main on Ubuntu with the same JDK 21. Both HTML reports are uploaded as downloadable artifacts. If a claim in this report doesn't match CI, CI wins.
