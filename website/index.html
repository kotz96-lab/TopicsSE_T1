Evaluating the BRICS Java Automata Library

Empirical software-engineering study for Topics in Software Engineering, Assignment 1. Four weeks of testing, mutation analysis, combinatorial interaction testing, metamorphic testing, differential comparison, and software-design evaluation applied to the dk.brics.automaton library at commit 582d8f3.

Two-line summary

BRICS is a 24-year-old academic Java library for finite automata and regular expressions. We built a rigorous test harness around it: 1948 tests, 77% line coverage, 51% mutation score. Along the way we surfaced three real defects and one API interoperability landmine.

Key finding

On RQ2 (does CIT improve mutation scores?): interaction strength alone doesn't move the needle. Going 2-wise → 3-wise → 4-wise under a weak oracle: 194, 205, 204 kills — flat. Under a stronger oracle that runs five metamorphic properties per row: 209, 229, 231 — a real bump at 3-wise, then plateaus. The weak-vs-strong gap grows (+15, +24, +27) as strength rises, so the two dimensions compound.
