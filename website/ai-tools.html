Use of AI Tools (§21)

§21 requires we disclose the AI tools used, what we used them for, how we validated outputs, and what mistakes we discovered and corrected. Full running log kept in docs/AI_TOOLS.md — this page summarises.

Tool used

Claude Code (Anthropic Opus 4.7 with 1M-token context window), operated as a coding-and-analysis assistant. The tool runs locally, has read/write access to the repo, and executes shell commands under human supervision.

What it was used for

  • Test generation. Most of the 180 hand-crafted JUnit5 tests were AI-drafted from BRICS's public API, then reviewed by us.
  • PICT model refinement. The parameter set, value ranges, and constraints in pict/models/regex.pict were AI-authored based on a reading of BRICS' source, then adjusted after the §9.4 experiment.
  • Combinatorial test harness. RegexRowBuilder, PictRegexTest, and PictMetamorphicTest are all AI-authored.
  • Metamorphic properties. All 18 properties in MetamorphicPropertiesTest are AI-drafted; we reviewed each identity for mathematical correctness.
  • Differential tests. DifferentialTest compatible-subset cases were AI-authored. The known-disagreements section was expanded after we surfaced the @-metacharacter finding.
  • Analysis writing. The SOLID analysis, refactoring proposals, mutation-analysis narrative, threats catalogue, and PICT rationale documents were all AI-drafted.
  • Website scaffolding. This site's HTML + CSS was AI-generated from the source docs.

Validation approach

Every AI-authored artifact was validated by at least one of:

  • Compilation + ./mvnw verify (all 1948 tests pass).
  • Cross-reference with BRICS Javadoc where AI made claims about behaviour.
  • Manual re-reading of any semantic claim before it landed in a report doc.
  • Independent verification via a distinct test flavour (e.g., a PICT test surfacing a mistake in the differential test set).

Mistakes discovered and corrected

The following mistakes were made by AI and caught by human review or by the test infrastructure itself. Full details for each are in docs/AI_TOOLS.md.

1. Wrong assumption about getCommonPrefix()

AI wrote a test assuming Automaton.getCommonPrefix() gives the semantic longest-common-prefix of the language. Test failed because getCommonPrefix walks the structural graph — a branching NFA gives empty prefix. Fixed by using a minimized DFA input.

2. Wrong assumption about isTotal()

AI wrote assertTrue(complement(makeEmpty()).isTotal()) assuming isTotal is semantic. It's actually structural. The failed test surfaced the API-clarity issue, which became Refactoring Proposal 2.

3. Wrong assumption about RegExp syntax flags

AI wrote assertThrows(IllegalArgumentException, () -> new RegExp("...", flagsWithoutIntersection)) assuming that disabling the intersection flag would make the parser reject the & character. Actually the flag change just makes & a literal. Fixed to test the language divergence directly.

4. Datatypes.main crash in @BeforeAll

AI wrote a DatatypesTest that invoked Datatypes.main() in a @BeforeAll block to populate the in-memory automaton cache. Blew up because main reads a companion resource src/Unicode.txt not shipped in the vendored source. Fixed by testing only the reachable surface (predicate methods).

5. @-metacharacter in "compatible subset" differential test

AI added [a-z]+@[a-z]+ as a compatible-subset case, assuming @ is a literal in BRICS. It's actually ANYSTRING. Test failed, and the failure surfaced the @-metacharacter finding. Also blocked PIT from running (PIT requires all tests green). Fixed by moving the case to "known disagreements" and using a neutral character (X) in the compatible-subset case.

6. PIT filter bug — the biggest one

AI wrote the per-strength CIT experiment using -Dgroups=<tag> to filter PIT by JUnit tag. -Dgroups= is a Surefire flag; PIT uses its own JUnit engine and silently ignores it. Consequence: every per-strength PIT run was actually executing the full 1948-test suite. The "flat" mutation scores across strengths that AI initially reported (~50.7% across all six combinations) were the full-suite score with PIT run-to-run noise, not real per-strength scores.

How we caught it: reviewer asked to verify the strong oracle was actually stronger. Inspecting the killingTest field in mutations.xml revealed kills coming from every test class in the suite, not just the tag-filtered one.

Fix: PIT's own filter flag is -DincludedGroups=<tag>. Re-ran all six combinations with the working filter. Corrected data is on the CIT page.

Lesson (worth quoting in the report): the AI-written PIT invocation was self-consistent (all filtered runs showed similar numbers, which read as "valid null result") but scientifically meaningless. Only human review of a specific hypothesis surfaced the flag bug. Automated correctness ≠ methodological correctness.

7. Wrong witness for Kleene-star idempotence property

AI wrote a metamorphic test for (X*)* = X* using (a|b)+ as a witness. (X+)* ≠ X+ because + doesn't accept empty and * does. Test correctly failed. Fixed to use (a|b)* witness.

8. Unicode-escape-in-comment compilation error

AI wrote a Java comment containing the literal text \u escapes. Java processes \u sequences even inside comments — the file failed to compile. Fixed by rewording the comment.

What we learned about AI-assisted testing

  1. AI is fast at scaffolding, weak at methodological sanity-checking. The filter-flag bug is the clearest example: the AI wrote self-consistent code that produced self-consistent (but wrong) results, and would have shipped it without human intervention.
  2. Tests that fail because of AI wrong assumptions often surface real findings. Two of our four refactoring proposals (isTotal semantic vs structural; @-metacharacter) came from AI making a plausible-but-wrong assumption about BRICS and the resulting failing test being informative.
  3. Compilation and green-suite are necessary but not sufficient. Bugs in AI-generated infrastructure can be invisible to those checks. Independent-oracle validation (does the strong oracle actually kill more mutants than the weak one, when isolated?) is required.
