Metamorphic Testing (§10)

Assignment §10 requires ≥10 metamorphic properties. We supply 18, covering union, intersection, complement, concatenation, minimization, determinization, Kleene star, regex round-trip, and prefix-closure.

The idea in one paragraph

Instead of asserting "for this input, expect this output" (example-based testing), metamorphic testing asserts relationships between outputs that must hold regardless of what the specific values are. For example, we don't need to know what language (a|b)*c accepts to check that A.union(B) and B.union(A) accept the same strings — union commutativity is a mathematical identity BRICS must respect.

Oracle used across all properties

Language equivalence via double inclusion: sameLanguage(A, B) := A.subsetOf(B) && B.subsetOf(A). BRICS' Automaton.equals compares hashCode (which is structural, not semantic), so we avoid it. subsetOf determinizes internally and is a genuine semantic check.

Example: property MR-6 (double complement) implementation

@Test
@DisplayName("[MR-6] ¬(¬A) has the same language as A")
void doubleComplement() {
    assertTrue(sameLanguage(a().get(), a().get().complement().complement()));
    assertTrue(sameLanguage(aStar().get(), aStar().get().complement().complement()));
    assertTrue(sameLanguage(abOr().get(), abOr().get().complement().complement()));
}

Interaction with CIT — a stronger oracle experiment

A subset of these properties (MR-3, MR-5, MR-6, MR-10, MR-12) is also applied per-PICT-row in PictMetamorphicTest. That gives us 754 additional PICT-generated automata × 5 metamorphic checks × 5 sampled inputs = 18,850 property assertions.

This is the "strong oracle" arm of the CIT experiment (see the CIT page). Combining metamorphic testing with combinatorial testing is exactly what assignment §9.3 and §10 suggest as an integration path, and the results (interaction strength + oracle strength compound) make the case that these two techniques are complementary rather than substitutes.

Violations found

None so far. All 18 properties hold across the tested automata. That's a positive finding: BRICS' regular-language algebra is implemented correctly on the operations we exercised. It also means the mutation-killing power of these properties comes from catching injected mutations of BRICS, not from exposing existing bugs.

Oracle limitations

  • Language-membership blindness to internal structure: two automata can accept the same language but have different state counts, determinism flags, or minimization state. Our oracle can't tell. That's fine for property tests (we care about language), but shows up in the mutation-testing analysis — some mutants that change internal state without changing language are invisible to us.
  • Sample-input limitation: we test each property on a handful of pre-chosen inputs. A property could theoretically fail on an input we didn't sample. The PICT-driven counterpart in PictMetamorphicTest widens this to 754 automata × 5 inputs, mitigating the risk.
