Analysis of 5 surviving mutants (§8)

Distilled into three failure patterns:

1. Behavioural-oracle blindness. Mutants change internal state (a determinism flag, a skipped minimize()) without changing the language. Example: BasicOperations.concatenate line 60.
2. Boundary blindness. Mutants misfire at Character.MAX_VALUE; our ASCII inputs miss them. Example: Automaton.getStartPoints line 410.
3. Output-content blindness. Mutants scramble toString content; our tests only assert non-null. Example: Transition.appendCharString line 136.

1 of 5 is behaviourally equivalent; the other 4 are killable with more focused assertions.

9 / 15

RQ2: Does CIT improve mutation scores?

It depends on the oracle. Interaction strength alone barely helps. Oracle strength alone helps modestly. Together they compound. And even the best combination shows diminishing returns past 3-wise.

Practical takeaway: use 3-wise with a strong oracle. Higher interaction strength alone doesn't pay off; oracle sensitivity is what makes the extra combinations bite.

Metamorphic testing (§10)

18 mathematical identities BRICS must respect (rubric requires ≥10). Sample:

  • Union commutativity: L(A ∪ B) = L(B ∪ A)
  • Double complement: L(¬¬A) = L(A)
  • De Morgan: L(¬(A ∪ B)) = L(¬A ∩ ¬B)
  • Minimize preserves language
  • Determinize preserves language
  • Concatenation associativity
  • Union / intersection idempotence
  • Kleene-star idempotence: L((A*)*) = L(A*)
  • Regex round-trip: L(parse(pattern.toString())) = L(parse(pattern))
  • Prefix-close accepts empty
All 18 hold. Positive finding — BRICS' regular-language algebra is correctly implemented on the operations we exercised.

Differential: BRICS vs java.util.regex (§11)

Compatible-subset patterns agree; five characters silently diverge.

Finding: BRICS reserves 5 default metacharacters that Java treats as literals.
Char BRICS meaning Java / PCRE / POSIX meaning
@ ANYSTRING (matches everything) literal @
# EMPTY (matches nothing) literal #
~ complement of following expression literal ~
& intersection of two expressions literal &
<name>reference to a named automaton literals

Someone porting a regex between engines gets silently wrong matching — no error, no warning. Direct implication for refactoring proposal 4.

Software design evaluation (§12)

SOLID verdicts

  • S: partially violated (Automaton is a god-class, 78 public methods)
  • O: closed — no interfaces to plug into
  • L: vacuous — no inheritance to violate
  • I: vacuously satisfied
  • D: violated — but arguably acceptable for a library

4 refactoring proposals

  1. Fix Datatypes.exists() NPE bug
  2. Clarify isTotal() semantic vs structural
  3. Replace getFiniteStrings null-return with exception or Optional
  4. Flip RegExp default flags to literal-first (interop fix)

All 4 proposals surfaced organically from writing tests, not from a code review pass. Different testing techniques expose different fault classes.

Conclusions

RQ2 answered empirically: CIT + strong oracle helps up to 3-wise; either dimension alone doesn't.
Real defects found: 1 NPE bug, 2 API-clarity issues, 1 interoperability landmine — all from test-writing friction.
BRICS' algebra is correct: all 18 metamorphic properties hold.
Reproducible: every number regenerates with two commands; CSVs are byte-identical thanks to pinned seed.

Limitations: single BRICS commit, Datatypes.buildAll unreachable without shipping a Unicode data file, and the "strong oracle" is one specific choice of five metamorphic properties — a different strong oracle might land differently.
