Stage Tests Detection rate
Empty (SmokeTest only) 1 ~0%
+ hand-written suite 181 51.6%

Detection rate = (killed + timed-out) / total mutations. Hand tests do the heavy lifting; extra test flavors move the rate only a little on their own. The final row also reflects a PIT scope fix (excluding Datatypes' unreachable build-time code), so its total-mutation denominator isn't directly comparable to the earlier rows. A mutant that could be caught by both a hand test and a metamorphic test only counts once.

10 / 17

Answer to RQ2, plain English

More test inputs alone doesn't help — if the checks are shallow, extra inputs just repeat the same shallow check.

Stricter checks alone doesn't help either — without varied inputs, they only fire on a few cases.

You need both. And even so, going past 3-wise adds almost nothing (only +2 detections 3→4).

Real gain is modest (+28 detections at 4-wise = ~13% over the weak checker). Small numbers but a clean, honest signal.

Metamorphic testing (§10) — 18 properties

  • Union commutativity: L(A ∪ B) = L(B ∪ A)
  • Double complement: L(¬¬A) = L(A)
  • De Morgan: L(¬(A ∪ B)) = L(¬A ∩ ¬B)
  • Minimize preserves language
  • Determinize preserves language
  • Concatenation associativity
  • Union / intersection idempotence
  • Kleene-star idempotence: L((A*)*) = L(A*)
  • Regex round-trip preserves language
  • Prefix-close accepts empty

Each property is tested on a small set of witness automata — typically 2–3 per property. Full list & source on the website.

All 18 hold. BRICS' regular-language algebra is correct on what we tested.

Differential: BRICS vs java.util.regex (§11)

Feed the same regex to both engines, compare their answers. ~38 compatible-subset patterns agree perfectly. Five characters silently diverge:

BRICS treats 5 ordinary ASCII characters as metacharacters. Java treats them as literals.
Char BRICS meaning Java meaning
@ ANYSTRING — matches every string literal @
# EMPTY — matches nothing literal #
~ complement of the next expression literal ~
& intersection of two expressions literal &
<name>reference to a named automaton literals

Someone porting a regex between engines gets silently wrong matching — no error, no warning. This is refactoring proposal 4 on the next slide.

Software design — SOLID by principle

SOLID = 5 OO design rules from Robert Martin. My verdict on BRICS:

PrincipleVerdict
Single responsibility
one class, one job		 Partially violated. Automaton.java is a god class — 78 public methods, doing data-holding, factory-making, facade-delegating, serialization, and global settings all at once.
Open/closed
extend without modifying		 Violated. Almost no interfaces to plug into — adding a new operation forces you to modify existing files rather than write a new class.
Liskov substitution
subclasses should work like parents		 Vacuous. BRICS uses almost no inheritance to violate.
Interface segregation
many small over one big		 Vacuously satisfied. Only one small interface exists.
Dependency inversion
depend on abstractions		 Violated — every dependency is on a concrete class. But defensible for a self-contained library where there's nothing to swap out.
14 / 17

4 refactoring proposals (§12.4)

All 4 surfaced from writing tests, not from a code review pass:

  1. Fix Datatypes.exists() NPE bug — supposed to return false for missing resources; actually throws NullPointerException. 3-line fix.
  2. Clarify isTotal() — the method's name reads "does this accept every string?" but it's only a structural shape check. Either rename it or make it actually semantic.
  3. Replace getFiniteStrings(a, limit) null-return — silently returns null when the language exceeds the limit, causing surprise NPEs downstream. Throw an exception or return an Optional.
  4. Flip RegExp default flags to literal-first — today @ # ~ & <> are metacharacters by default, breaking interop with every other regex engine. Make them literal unless the caller opts in.

Conclusions

RQ2: combinatorial testing helps only when the checker is strict enough to notice differences. Neither more input combinations alone, nor stricter checks alone, moves the mutation score much. Together they add ~13% more kills — a real signal, though not huge — and going past 3-wise gives essentially nothing.
Real defects found: 1 NPE bug, 2 API-clarity issues, 1 interoperability landmine — all from writing tests, not from a code review.
BRICS' algebra is correct: all 18 metamorphic properties hold.

Limitations: single BRICS commit, Datatypes.buildAll unreachable, and the "stricter" checker is one specific choice of five metamorphic properties — a different one might land differently.
